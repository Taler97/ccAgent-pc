# PC 端（pcAgent）更新文档（2026-08-07）

> 对比 pcAgent 最近一次 git 提交 `7032a2e`（未提交的工作区变更）。
> 变更规模：58 文件，+1613 / -360

---

## 1. WS 消息架构重构（三通道隔离 + Handler 分发）

- **MessageDispatcher 新增**：按消息类型分发到三条独立虚拟线程通道，互不阻塞
  - `dialogChannel`：对话/Agent 执行（EXECUTE、EXECUTE_PLAN、CANCEL_EXECUTION、CANCEL_PLAN、ROLLBACK_DIALOG、TOOL_APPROVAL）
  - `utilChannel`：工具操作（CREATE_SESSION、FILE_LIST_REQ、QUERY_PROGRESS 等）
  - `controlChannel`：心跳/控制（PING、ON_KICK），最高优先级
- **MessageRouter 解耦为纯分发器**：注册 5 个 Handler（Session / Execution / File / Status / Misc）+ 可选 ConfigHandler，行数由 348 收敛到 81
- **seqId 锁策略细化**：
  - 对话协作信号（EXECUTE_PLAN / CANCEL_PLAN / TOOL_APPROVAL / CANCEL_EXECUTION / ROLLBACK_DIALOG）**跳过锁**，保证能打断 EXECUTE 持有的 future.get(120s) 阻塞，避免 APPROVAL_TIMEOUT
  - 对话类 EXECUTE 加锁保护执行串行化；工具/控制类消息无锁，避免只读查询被 EXECUTE 阻塞

## 2. 新增 ConfigHandler（LLM 配置热更）

- 处理 `UPDATE_LLM_CONFIG` / `QUERY_LLM_CONFIG`
- 调用 `DeepSeekLlmAdapter.updateThinkingConfig` 免重启生效，并同步 `AppConfig`
- 前端顶栏"LLM 思考模式"开关即走此链路

## 3. Skill 技能体系（core/skill）

- 新增 `Skill` / `SkillLoader` / `SkillRegistry`，对齐 Claude Agent Skills 目录约定：
  - `skills/<name>/SKILL.md`（目录式）或 `skills/<name>.md`（单文件式）
  - 解析 frontmatter（YAML：name / description / expert）+ 正文 prompt
- 可空注入 SimpleOrchestrator（不启用 skill.md 注入时不影响）

## 4. MCP 工具接入（plugins/plugin-tools/mcp）

- 新增 `McpClientManager` / `McpConfigLoader` / `McpServerConfig` / `McpToolExecutor` / `DefaultMcpAdapter`
- 支持 stdio / HTTP 两种 transport 的 MCP server 配置、连接与热重载；pom.xml 增加对应依赖

## 5. 黑板演进为 LangGraph 风格（缩略型黑板）

- 新增 `BlackboardSchema` / `FieldSchema`（api 模块）与 `YamlBlackboardSchema`（core，YAML 配置驱动）
- `TaskContextImpl.putArtifact` 重构：
  - 按 schema 的 mergeStrategy 合并：`replace`（幂等覆盖）/ `append`（List 累积）/ `merge`（Map 合并）
  - `futures.compute` 原子合并；旧 Future 未完成时直接 complete 唤醒消费者（修复 P0 挂起 bug）
  - 新增 `missingKeys`：清单/磁盘有记录但产物缺失时上报，供上层决策

## 6. 执行进度上报与查询

- `StatusHandler` 新增 `QUERY_PROGRESS`（返回执行进度快照，供看板刷新主动拉取）
- `SessionHandler` 新增 `WORKSPACE_VALIDATE_REQ` / `SESSION_STATUS_REQ`（工作区路径校验与会话绑定状态）

## 7. 三端版本接口

- `Constants` 从 pom.properties 读取 `APP_VERSION`（开发环境 fallback `dev`），新增 `APP_NAME`
- `MiscHandler` 新增 `VERSION_REQ` → `VERSION_RES`，供云端聚合版本号

## 8. 执行引擎与治理

- **SimpleOrchestrator**：
  - 计划状态字符串统一为 `RUNNING`（替代 EXECUTING）
  - 启动时 `recoverInterruptedPlans` 恢复中断计划（RUNNING 状态 + 磁盘恢复）
  - 订阅 `LlmCallCompletedEvent` 按 seqId 累积 token（total/cached），保存对话时数据就绪
  - 注入 SkillRegistry（可空）
- **RollbackManager** 加固（git 会话级回滚）
- 文件操作接口统一携带 sessionId

## 9. 单实例守护

- 删除旧 `AgentDaemon.java`，能力并入 `AgentMain`（`--background` 模式，旧参数 `--headless` 兼容）
- 新增 `DaemonLock`：基于 `daemon.lock` 文件锁 + `daemon.pid`，保证同一时刻仅一个引擎进程，获取失败则拒绝启动

## 10. 其他

- DeepSeekLlmAdapter 支持 thinking 模式配置（thinkingEnabled / reasoningEffort）
- 新增测试：`MessageChannelIsolationIntegrationTest`、`SeqLockManager` 并发/单测、`MessageRouterTest`、`DaemonLockTest`、`BlackboardTimeoutIntegrationTest`、`PlanStatusConsistencyIntegrationTest`、`YamlBlackboardSchemaTest`、`FileArtifactStoreTest`、`TaskContextImplMergeTest`、`SkillLoaderTest`、`DispatcherProgressIntegrationTest` 增强等

## 11. 本端在端到端链路中的接口

| 能力 | 本端处理的消息 |
|------|--------------|
| 版本查询 | `VERSION_REQ` → `VERSION_RES` |
| 连通测试 | `PING` |
| 思考模式配置 | `UPDATE_LLM_CONFIG` / `QUERY_LLM_CONFIG` |
| MCP 管理 | `MCP_STATUS_REQ` / `MCP_IMPORT_REQ` |
| 技能列表 | `SKILL_LIST_REQ` |
| 执行进度 | `QUERY_PROGRESS` 快照 |
| 工作区校验 | `WORKSPACE_VALIDATE_REQ` / `SESSION_STATUS_REQ` / 路径穿越校验 |

## 12. 注意事项

1. 本文档描述的所有改动均处于工作区未提交状态，需在 pcAgent 仓库内 `git add` / `commit` / `push`
2. 根目录出现 `*.log`、`jstack-*.txt`、`cp.txt`、`cp2.txt` 等临时文件，建议加入 `.gitignore` 后清理
